1. 시스템 개요 — C 프로그램이 바라보는 전체 구조

PS(Cortex-A9)의 C 프로그램은 GP0(AXI-Lite)로 GPIO·DMA 레지스터에 접근해 링크를 기동하고(②) 전송을 지시하며(③), HP0(64-bit)는 DMA가 DDR 버퍼를 읽고 쓰는 데이터 전용 경로다(⑤ 비교는 CPU가 수행). PL 데이터 경로는 user_clk 78.125 MHz 하나로 흐르고, 링크 리셋 시퀀스·상태 수집은 GT와 무관하게 도는 init_clk 62.5 MHz가 맡는다. 현재 기동값은 VIO 소유(vio_ctrl_sel=1, PMA 루프백=2)이므로 C는 ②를 건너뛰고 채널 상승만 기다린다.

2. 블록 디자인 상세 — aurora_cam.bd 전체 셀과 넷

현재 BD의 셀 17개(PS7 1 + IP 11 + RTL module reference 5)를 세 개의 면으로 나누어 그렸다. 박스 테두리 색 = 클럭 도메인(범례 참조), ◆ = 클럭 도메인이 바뀌는 지점(CDC)이다. 붉은 실선이 C 프로그램의 레지스터 접근 경로, 회색 점선 사각형(prbs_gen·prbs_check의 PRBS 기능, vio_link)은 C 실행 중 사용하지 않는 경로다.

3. 클럭 도메인과 리셋 — C 프로그램이 기다리는 시점의 물리적 의미

설계에는 클럭이 4개 있고, 서로 동기 관계가 없는 독립 도메인이다. GT에서 파생되는 user_clk은 링크가 내려가면 멈춘다. 그래서 "링크를 다시 올리는" 로직(리셋 시퀀서)은 반드시 멈추지 않는 init_clk에서 돌아야 하고, C 프로그램이 channel_up을 기다리는 것은 결국 user_clk이 살아났다는 뜻이 된다.

3.3 링크 기동·리셋 시퀀스 (run 0→1 부터 DMA 시작까지)

주의 — user_clk이 멈추는 구간: run=0(리셋) 구간, power_down=1 구간. 이때 user_clk 도메인 신호(예: channel_up 동기화기 출력)는 마지막 값을 유지한다. C는 run을 0으로 만드는 경로를 쓰지 않고(VIO 소유), 재기동 시 262 µs 시퀀스와 sys_reset_out을 거쳐 리셋이 다시 걸리므로 안전하다. 링크가 떨어진 상태에서 오래된 channel_up=1이 보일 수 있는 잔여 위험은 이전 분석 참조(마스킹 옵션).

근거: rtl/link_ctrl.v 96~129행(시퀀서·RST_DELAY=16384, 16ns=62.5MHz), 146~151행(urst 2FF·user_aresetn), 258행(tx_fifo_aresetn 255카운트+pll_not_locked), sw/loopback_test.c 96~124행(폴링 1ms×1000, 10ms 대기, err_clear), PG046 리셋 순서(gt_reset 먼저 해제)

4. 데이터 경로 — 프레임 1개가 지나는 10단계와 각 구간의 규격

C가 MM2S_LENGTH에 1,843,200 B를 쓰는 순간(③) 아래 체인이 자동으로 흐른다. 한 프레임 = 720라인 × 640 beat(32b)이며, packetizer가 라인마다 헤더 1 beat를 붙여 Aurora 프레임 1개(641 beat + CRC)로 만든다. depacketizer가 헤더를 떼어 내면 원래 460,800워드만 S2MM으로 들어가고, EOF 라인의 마지막 beat가 TLAST가 되어 DMA 전송을 끝낸다(④ IOC).

4.1 패킷 형식 — "Aurora 프레임 1개 = 라인 1개" (비디오 프레임 1개 = 720라인)

근거: rtl/line_packetizer.v 헤더 정의(TYPE/FMT/SOF/EOF/FRAME_ID/LINE, 라인당 헤더 1 beat), rtl/line_depacketizer.v(헤더 제거·순번/길이 검사·0xDEADBEEF 주입), BD 파라미터 H_BEATS=640·V_LINES=720·TLAST_PER_LINE=0, Aurora CRC 활성. 프레임 백투백 전송 시 실제 페이로드률은 헤더 1/641 오버헤드로 ≈312.0 MB/s, 프레임 경계 idle·CRC 로 약간 더 낮아짐(실측 참고 ~309 MB/s)

5. C 프로그램 실행 흐름 — sw/loopback_test.c 전체 순서도

C는 인터럽트 없이 레지스터 쓰기→폴링→메모리 비교만으로 전체 데이터 흐름을 제어한다. 모든 접근은 ①~⑤ 다섯 동작의 반복이며, 오른쪽 상자는 프레임 1개(run_frame)의 내부 순서다.

근거: sw/loopback_test.c 76~79행(elapsed_us), 81~94행(show_status), 96~124행(link_start), 126~131행(dma_reset), 133~184행(run_frame), 186~209행(main). 타임아웃: 링크 1 s·프레임 500 ms

6. 프레임 1개의 시퀀스 — CPU·캐시·DMA·PL·DDR 상호작용

run_frame 한 번의 시간 순서다. 붉은 점선이 C의 능동 동작, 실선이 하드웨어 데이터 이동이다. t0~t1이 UART에 출력되는 us(전송 시간)의 측정 구간이다.

근거: sw/loopback_test.c 133~184행, PG021 simple 모드 전이(무장→RS→전송→IOC), Xil_DCache*(L1+PL310), XTime(COUNTS_PER_SECOND)
